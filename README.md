# WeekSync API

Backend API for **WeekSync**, built with [NestJS](https://nestjs.com/) and TypeScript.

## Tech Stack

- **Framework:** NestJS 12 (Node.js, Express platform)
- **Language:** TypeScript
- **Database:** PostgreSQL via [Prisma ORM](https://www.prisma.io/) (`@prisma/client` + `prisma` CLI, pinned to v6.x)
- **Validation:** class-validator / class-transformer
- **Testing:** Jest (unit + e2e), Supertest
- **Linting/Formatting:** oxlint, Prettier

## Project Structure

```text
week-sync.api/
├── prisma/
│   └── schema.prisma          # Database schema (models, datasource, generator) used by Prisma
├── src/
│   ├── main.ts                # Application entry point (bootstraps Nest app, starts HTTP server)
│   ├── app.module.ts          # Root module - wires together controllers/providers/feature modules
│   ├── app.controller.ts      # Root HTTP controller (route handlers)
│   ├── app.controller.spec.ts # Unit tests for the root controller
│   ├── app.service.ts         # Root service (business logic used by the controller)
│   ├── prisma/
│   │   ├── prisma.module.ts   # Global module exposing PrismaService to the whole app
│   │   └── prisma.service.ts  # Wraps PrismaClient, connects/disconnects with the app lifecycle
│   └── project/                # Example feature module (CRUD)
│       ├── project.module.ts
│       ├── project.controller.ts   # REST routes: POST/GET/PATCH/DELETE /project
│       ├── project.service.ts      # Business logic, talks to the DB via PrismaService
│       ├── dto/                    # Request payload shapes + validation decorators
│       └── entities/                # Response shape returned to clients
├── test/
│   ├── app.e2e-spec.ts        # End-to-end tests (spin up the app, hit real routes)
│   └── jest-e2e.json          # Jest config for e2e tests
├── dist/                      # Compiled JS output (generated by `npm run build`)
├── nest-cli.json              # Nest CLI configuration
├── tsconfig.json              # Base TypeScript config
├── tsconfig.build.json        # TypeScript config used for production builds
├── jest.config.ts             # Jest config for unit tests
├── oxlint.json                # Linter configuration
└── package.json                # Scripts and dependencies
```

**How it fits together:** `main.ts` boots the app using `AppModule`. `AppModule` is the root module where new feature modules (controllers + services + their own module file) get registered as the API grows. Each feature should follow the same pattern: `*.module.ts` (wires it up) → `*.controller.ts` (defines routes) → `*.service.ts` (business logic), following Nest's modular, dependency-injection based architecture.

## Getting Started

1. **Clone the repository**

   ```bash
   git clone <repository-url>
   cd week-sync.api
   ```

2. **Install dependencies**

   ```bash
   npm install
   ```

3. **Configure environment variables**

   Create a `.env` file at the project root:

   ```env
   DATABASE_URL="postgresql://<user>:<password>@<host>/<database>?sslmode=require"
   PORT=3000
   ```

   - `DATABASE_URL` — connection string for the Postgres database used by Prisma. `.env` is gitignored; never commit real credentials.
   - `PORT` — port the API listens on (defaults to `3000` if unset).

4. **Set up the database**

   Apply the Prisma schema (creates the database tables):

   ```bash
   npx prisma migrate dev --name init
   ```

   Whenever `prisma/schema.prisma` changes, regenerate the Prisma Client:

   ```bash
   npx prisma generate
   ```

## Deployment

### Deploying to Vercel (recommended for this project)

NestJS is a long-running server framework, not a static/Next.js app, so it's deployed to Vercel as a single serverless function that wraps the Nest app. This repo already includes the wiring for that:

- [`api/index.ts`](api/index.ts) — boots the Nest app once per cold start (via an Express adapter) and reuses it across invocations.
- [`vercel.json`](vercel.json) — routes every incoming request to that function.
- `prisma/schema.prisma` — generator includes `binaryTargets = ["native", "rhel-openssl-3.0.x"]` so the Prisma engine matches Vercel's Amazon Linux runtime.
- `package.json` — has a `postinstall: prisma generate` script, since Vercel reinstalls dependencies on every deploy and the generated client isn't committed.

Steps:

1. **Push this repo to GitHub/GitLab/Bitbucket** (Vercel deploys from a git provider).
2. **Import the project** at [vercel.com/new](https://vercel.com/new) and select the repo.
3. **Set environment variables** in the Vercel project settings (Settings → Environment Variables):
   - `DATABASE_URL` — use Neon's **pooled** connection string (usually the host with a `-pooler` suffix) since serverless functions can open many concurrent connections.
   - Do **not** set `PORT` — Vercel manages the port for serverless functions.
4. **Deploy** — Vercel runs `npm install` (triggering `postinstall` → `prisma generate`), then serves every route through `api/index.ts`.
5. After deploying, apply any pending migrations against the production database from your machine (Vercel doesn't run migrations automatically):

   ```bash
   DATABASE_URL="<production-database-url>" npx prisma migrate deploy
   ```

Or deploy from the CLI instead of the dashboard:

```bash
npm install -g vercel
vercel        # preview deployment
vercel --prod # production deployment
```

### Other deployment options

### 1. Build a production bundle

```bash
npm run build
```

This produces a compiled app in `dist/`, entry point `dist/main.js`.

### 2. Run in production

Set the required environment variables (at minimum `PORT`, plus any added later), then run:

```bash
npm run start:prod
```

or directly:

```bash
node dist/main.js
```

### 3. Deploying to a server / container

A typical deployment flow:

```bash
npm ci --omit=dev   # install only production dependencies on the target machine
npm run build       # build step can also run in CI before shipping the dist/ output
node dist/main.js   # start the app
```

If deploying with Docker, a minimal setup looks like:

```dockerfile
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build
EXPOSE 3000
CMD ["node", "dist/main.js"]
```

### 4. Managed deployment via NestJS Mau (optional)

The project includes `@nestjs/mau` as a dev dependency, which allows deploying directly to AWS via NestJS's official platform:

```bash
npm install -g @nestjs/mau
mau deploy
```

See the [Mau documentation](https://mau.nestjs.com) for account setup and configuration details.
